## Repo-level aspects

**llm-kb-as-root-pattern** — every other skill declares itself an application or specialization of `llm-kb` (`llm-must-read-kb` "Extends `Skill(llm-kb)`"; `llm-discourse-graph` "Built on the `llm.kb` pattern"; `llm-design-kb`'s numbered layers; `llm-subtask`'s `todo.kb/`/`ideas.kb/`; `llm-vitals`' `requires:`). Layering is by prose citation only — no mechanical inheritance anywhere.

**skill-naming-grammar** — `llm-` prefix on skills; scripts as `{supertool}-{noun}[-{verb}]`, all in `bin/`, no language suffix (`docs/dev/adr/2025-12-09-001`). **strict-CLI-grammar** — the seven creator/init scripts take `-C <dir>` (default `.`) and `--title`; no positional arguments anywhere; malformed calls fail loudly before touching files (`2026-07-09-000`). **dated-record-naming** — `YYYY-MM-DD-NNN-slug.md`, `NNN` resets daily, `ls` is the timeline, no registry (`llm-kb/references/dated-slug-filename.md`); `bin/claude-slug` centralizes slugification. **skeleton-directories** — templates ship as a literal target-shaped tree (`llm-collab/.../2025-12-02-002`). **lib-python-testable-scripts** — `lib/python/{libname}/` package, `bin/` symlinks, `uv run --script` PEP-723 shebangs, `*_test.py` beside code (`2025-12-09-003`). **loud-missing-directory** — required dirs are checked, never `mkdir -p`'d silently; the error names `$PWD` and a `mkdir -p … && !!` recovery (`2025-12-09-000`).

**setup-plus-depends-self-registration** — `SKILL.md`'s `setup:` instructs consumer projects to add a `depends:` entry to their `CLAUDE.md` frontmatter so future sessions load the skill (`2025-12-03-000`). **action-based-load-triggers** — skill descriptions must state detectable, action-tied triggers, not subjective ones ("complex project", "many sessions") (`2025-12-03-001`). **frontmatter-directives** — `requires:` = MUST read before acting; `depends:` = read when relevant. **claudemd-vs-skillmd-semantics** — `CLAUDE.md depends:` = what loads when working *in* this directory (derived from directory structure; self-reference legal); `SKILL.md setup:` = what consumers configure (`2025-12-11-000`). **frontmatter-stripping-workarounds** — a comment on the first `---` (`#13003` for CLAUDE.md, split second block `#13005` for SKILL.md) so the model can see the frontmatter.

**kb-suffix-unification** — all skill-managed collections are `.kb/`; the prior `.d`/`.kb` split was diagnosed as "invented post-hoc to justify the status quo" (`2025-12-11-001`). **managed-by-ownership** — `managed-by: Skill(<name>)` in frontmatter, validated by a schema `const` so write-time validation enforces it. **skill-uri-scheme** — `skill://<skill>/<path>`, resolved in-memory via `~/.claude/skills/`, replacing the resolver-less `Skill(<name>)` notation for file references. **jsonschema-beside-collection** — `$CATEGORY.jsonschema.yaml` beside `$CATEGORY.kb/`, Draft-07-in-YAML, `additionalProperties: false` recommended; shared fragments in a `jsonschema/` subdir reused by whole-file `$ref`; canonical schemas publish a strict root plus an open `#base` anchor so classes extend without forking. **migrations-as-a-collection** — `llm-kb/migrations.kb/`: one dated entry per schema/convention migration (`status`/`scope`/`supersedes`/`why`) with an optional same-stem sibling dir holding `migrate.sh`/`validate.sh`.

**two-record-kinds** — ADR (why; with Alternatives Considered) and devlog (when; session narrative), both dated, `ls` as index, newest wins. **docs-vs-docs-dev** — `docs/` user-facing, `docs/dev/` developer-facing (`llm-collab/.../2025-12-11-001`). **design-tower** — numbered `NNN-layer` stores with upward `why:` chains; auxiliary collections stay unnumbered. **skill-local-must-read-bank** — `llm-kb` ships `SKILL.kb/must-read/` with an `IMPERATIVE` making `ls -RF` the first action on load. **self-audit-battery** — 13 named audits (bloat, claudemd-completeness, claudemd-enumeration, collection-homogeneity, cross-references, enumeration-completeness, filename-discipline, orphan-entries, per-file-scope, promotion-signals, schema-potential, synthesis-file-value), each Goal/Procedure/Recovery, swept in urgency tiers by `procedures.kb/run-self-audits.md`. **validators** — `bin/llm.kb-validate` (frontmatter vs auto-detected schema, recursive, skips `CLAUDE.md`) and `bin/llm.kb-validate-links` (reference resolution), a split the docs call temporary.

## llm-kb

Function. Defines the `.kb/` pattern — homogeneous one-item-per-file collections with optional schema-validated frontmatter, maintenance guides and synthesis files — and ships the validator.

Aspects. **collection-anatomy** (`$CATEGORY.kb/` + sibling `$CATEGORY.md` synthesis + `$CATEGORY.jsonschema.yaml` + per-directory `CLAUDE.md`); **ls-is-the-index** (discovery is `ls`; "Never enumerate in CLAUDE.md"; synthesis rolls up, never lists); **claudemd-is-a-maintenance-guide** (after reading it an agent knows what *belongs*, not what is *present*: what belongs / what does not / when to add); **synthesis-file-frontmatter** (`last-updated:` required if the file exists); **item-plus-elaboration** (`$ITEM.md` + `$ITEM.kb/`; for decision points the `.md` poses the question, the `.kb/` holds one file per option, and on close the `.md` is rewritten to stand alone); **recognizing-the-shape** (the pattern is its end state, so a suffix-less ad hoc directory or scattered files are the same pattern in the wrong shape; a promoted collection inherits its parent scope's naming convention); **naming-rules** (kebab-case, name-signals-content, ordering prefixes zero-padded to twice the digits expected); **category-as-query-filter** (`head -n999 $CATEGORY.kb/*.md` loads a category in one operation); **four-quality-passes** (enumeration completeness, per-file scope with a 50-token trip wire, schema potential, validation); **successive-subtraction** for factoring a large doc; **stub-missing-entry** with a one-level cascade bound; **methodology-kb-self-application** (`docs/dev/` holding `concepts.kb/` — case-study, failure-mode, principle, procedure — plus `case-studies.kb/` and `procedures.kb/`).

Stated intent. Origins are Unix `.d/` directories plus schema validation and agent maintenance guides (`references/pattern-guide.md`). No enumeration because "`ls` stays current, documentation becomes stale instantly" (ibid.). Lean toward `.kb/` because "going from `.md` to `.kb/` later requires renaming, splitting, and writing a new `CLAUDE.md`" (`references/creating-a-new-kb.md`). `skill://` exists because `Skill(<name>)` was "a bespoke notation with no resolver and no normative referent" (`docs/dev/adr/2026-05-18-000`). Promotion is taught as recognition rather than procedure because an agent demonstrably failed to recognize an already-split ad hoc directory (`docs/dev/adr/2026-07-09-000` + its paired case study).

Contradictions. **methodology-home-split** — `SKILL.md`'s "Methodology kb" section puts `procedures.kb/` under `docs/dev/` and names `post-mortem.md`; that file lives in `SKILL.kb/procedures.kb/`, while `docs/dev/procedures.kb/` holds one unrelated entry — two collections of the same type in two homes. **dangling-collections** — `SKILL.md`, `docs/dev/procedures.kb/CLAUDE.md`, `concepts.kb/CLAUDE.md` and `must-read/after/distilling-from-a-raw-source.md` all cross-reference `failure-modes.kb/`, `principles.kb/`, `glossary.kb/`; none exist — precisely the `cross-references` audit's own failure mode. **schema-optionality** — `SKILL.md` makes schemas optional for prose-only collections; `pattern-guide.md` lists "Skip schema creation" as an anti-pattern. **singular-vs-plural-collections** — `procedures.kb/promote-to-collection.md` prescribes `tools.md → tool.kb/` (singular); `SKILL.md` and `complete-example/` use plural.

## llm-discourse-graph

Function. Epistemic knowledge graph over `.kb/`: five collections modelling what is believed, why, how confidently, and from where.

Aspects. **five-collections** (`questions`, `claims`, `deductions`, `sources`, `definitions`); **core-wiring** (question `candidate-resolutions` → claim; deduction `conclusion` → claim or deduction; `premises` → claims; `depends` = needs context from, implying neither support nor refutation); **deduction-polarity** (`kind: entailment|contradiction`) and a **status enum** (`asserted|contested|retracted`) shared by claims and deductions; **field-presence semantics** (a question's state derives from presence of `resolved` / `candidate-resolutions`); **any-node-elaborates** (`$ITEM.md` + `$ITEM.kb/`, parent IS the roll-up — convention, not configuration); **file-relative-paths**; **placement-at-narrowest-scope** as a judgment made once; **similarity-groups** (`similars`, `holotype`; status deferred); **open-world-assumption**; **schemas-beside-collections** in `jsonschema/`; **normative-companion split** — non-truth-apt content belongs in a design tower, not here.

Stated intent (`docs/dev/adr/`). Five types after surveying IBIS, Toulmin, Argdown, micropublications, nanopublications, schema.org, Wikidata, SKOS, AGM (`2026-03-02-000`); Evidence folded into claims because an observation "is a propositional assertion" that can be contested and retracted like any other (ibid.); "Claim" over "Assertion" as the cross-field term of art (`-003`); any-node elaboration because question-only scoping "added a rule without adding value" (`-002`); OWA because the format models "knowledge-in-formation, not settled encyclopedic facts" (`-005`); `user`/`assistant` as source *kinds* rather than a new singular field, since `sources.kb/` "already exists precisely to hold reusable provenance nodes" (`2026-07-03-001`).

Self-correction of note. **lexical-scoping-reversal** — `2026-03-02-001` chose ancestor-walking path resolution whose own consequences required tooling; `2026-07-03-000` supersedes it on the finding that "No such tool was ever built", and that the only live enforcement (`llm-kb`'s cross-references audit) had always assumed file-relative semantics. The fleet's cleanest case of a shipped mechanism that never existed.

## llm-triggers

Function. Design-phase successor to `llm-must-read-kb`; a 10-line `SKILL.md` stub whose content lives in `design.kb/`.

Aspects. **the-floor** — a filename-indexed bank scanned at plan time, requiring zero runtime support, and explicitly "not a fallback; it is the semantics"; mechanical binding strengthens delivery of the same meaning and never replaces it, so per-consumer support is non-lockstep and an unbound trigger is never "broken". **interpretation-not-compilation** — one static interpreter shim per interception point reads trigger files at fire time, so "staleness is structurally impossible" and observability is a coverage report rather than a staleness check. **condition-vocabulary** — three neutral kinds (command pattern, path pattern, lifecycle point) admitted by a floor-noticeability test ("about to run `git commit`" passes; "PreToolUse fired with matcher X" fails). **one-bank-format** for action- and judgment-shaped triggers alike, enforcement strength varying by detectability. **trigger-desc grammar** — juncture (`at`/`before`/`when`/`after`) × self-disambiguating type (date/instant/`file:`/prose), shared by task deferral and future-work `trigger:`. **v1-junctures-carried-forward** unchanged. **use-cases.kb/** with 14 seeded entries.

Stated intent (`docs/dev/adr/2026-07-19-001`). In-suite packaging because a triggers-without-kb consumer "is not a deferred case, it's a non-concept"; compilation rejected because "a compiled artifact re-introduces, in generated form, the exact staleness class v1 suffered in prose form"; prior art named as git hooks and `pre-commit`.

Contradiction. **two-skills-one-territory** — that ADR records it: `llm-must-read-kb` (working v1 banks) and `llm-triggers` (v2 design) "are now two skills describing overlapping territory… until the fold-in at build time".

## llm-chat-librarian

Function. Turns raw LLM conversation exports into navigable, extractable knowledge via a seven-command pipeline.

Aspects. **seven commands** documented one-per-file in `commands/` (`chatlib-digest|survey|triage|segment|assess|extract|index`), grouped by phase (foundation, discovery, organization, evaluation, extraction, navigation); **suggested 8-step workflow** in which `chatlib-digest` runs twice — raw tree, then segmented view; **explicit skip rules** per step ("Not every conversation needs all steps"); **digest-first** as the stated efficiency lever (everything downstream reads summaries, not raw messages); **symlink-don't-copy** (organized views point at source data — single source of truth); **provenance-over-prescription** (every extracted artifact names its origin, its endorser, and what is lost when read standalone); **dependency-order-over-conversation-order**; **ask-don't-infer** when project state is ambiguous; **format-agnostic once one file per message** exists.

Note (description): this is the fleet's only skill whose unit is a `commands/` directory rather than a `.kb/` — and the T4 probe recorded in `docs/dev/adr/2026-07-19-001` found that skill-bundled `commands/` directories do not resolve as slash commands in Claude Code.

## claude-realignment

Function. Diagnoses communication breakdowns by tracing a conversation turn-by-turn to the point where understanding diverged.

Aspects. **single-file-skill** (28 lines; no `.kb/`, no scripts, no `setup:`) — cited in `design-next.kb/040-design.kb/class-package.md` as the size discipline a class conventions page should keep; **description-as-trigger** (SHOUTING, pejoratives, sarcasm, repeated corrections or tool rejections, failing clarifications); **calm-first re-entry** (stop generating candidate actions; re-read the directive verbatim; scan the actual tool-call history, not memory of it; ask once, narrowly); **correction-is-data-about-the-parse**, not just the action; **five-step procedure** (bound it → trace each turn → find the root → pivotal word → rails?); **fixed output shape** (timeline, pivotal word with both readings, rails assessment).

## design-next.kb — the incumbent's own stated direction

Thesis (`010-mission.md`, quoted): give one operator and "every agent that drops into their 10–20 parallel sessions a day" a "single coherent system for three jobs that today are spread across nine organically grown skills" — **durable knowledge**, **attention**, and **convention enforcement** ("the rules that must hold, holding by mechanism rather than by reminding the model harder"). v1 "proved the core bets (filesystem as database, small homogeneous files, schema-validated frontmatter, dated records) and disproved one: that prose emphasis can enforce behavior." Success is "an agent orients in under a minute; conventions hold without IMPERATIVE blocks; a fix to shared behavior lands in exactly one place; the operator stops finding half-landed renames."

**numbered-store-layout** — `NNN-name.jsonschema.yaml` + `NNN-name.kb/` triples at 010/020/030/040/070, `why:` edges upward, a shared `jsonschema/` holding `why` and `decision-lifecycle`.

**goals** (`020-goals.kb/`): designed-for-deletion, mechanism-over-exhortation, native-first, runtime-portability, self-application, session-continuity, single-source-improvement, token-economy, write-economy. **requirements** (`030-requirements.kb/`): action-triggers-enforced-deterministically, authorship-boundary, classes-detach-cleanly, coupling-is-adapter-only, dated-records-are-primitive, degrade-gracefully, filesystem-as-database, judgment-triggers-remain-scannable, procedures-are-tools, spec-cited-never-restated, validators-outlive-migrations, wake-conditions-are-noticed, writes-name-their-read-back.

**core-and-classes** — four kinds: one spec (formats only), one class-blind engine, one class package per domain (schema, templates, conventions page, triggers, checks), many data instances. Dependency rules: class→spec required; class→class citation and composition only, never subclassing; class→engine verb citation with a stated degradation; engine→class forbidden as a source dependency (runtime discovery only); spec→anything forbidden. **kb-spec** — collection, entry, synthesis file, maintenance guide, dated record, linked node, cross-references, `requires:` as the only load directive, naming; "the spec never appears restated in a skill, rule, or CLAUDE.md"; a meta-schema validates class schemas. **kb-engine** — one `kb` CLI (`new`, `init`, `validate`, `promote`, `doctor`, `query`) with a discovery contract making `git rm -r <class-package>` drop that class from every surface; "agents are taught to *recognize* situations and call the engine — never to execute mechanical steps from prose". **memory-policy** — a runtime's auto-memory is admitted only as observations; deliberate knowledge lives only in a kb; a `kb doctor` check flags kb-shaped `MEMORY.md`.

What it proposes to drop or replace: "V1's unit was the vertical silo… which is why definitions drifted apart and improvements had to be re-landed per skill." `llm-kb` splits into spec + engine; `llm-collab` **dissolves** (devlog fails the residue test; decisions become settled questions; scripts become engine commands; skeleton becomes `kb init`); `llm-design-kb` and `llm-discourse-graph` become the design and discourse classes; `llm-must-read-kb` becomes the trigger class; `llm-subtask` becomes the task class with enforcement moving adapter-side; `llm-vitals`, `sessions.kb` and the personal must-read bank become data; `claude-realignment` and `llm-chat-librarian` stay standalone. The eight `bin/` scripts, the skeletons, and the prose promotion procedure are all named as absorbed.

Open by the tower's own marking: `core-and-classes`, `class-package`, `kb-engine` and `memory-policy` all carry `status: proposal`, with four `[!QUESTION]` blocks between them (is the conventions page the delivered teaching; does class-local code have plain consumer status; does teaching consolidate cross-class or stay per-package; are declarative checks expressive enough for `doctor` + `new`). Ratifying these is an open sweep in the repo's `.claude/todo.md`.
